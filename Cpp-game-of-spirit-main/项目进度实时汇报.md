### 1.2 IScene 抽象基类

**文件清单：** src/IScene.h · src/IScene.cpp

**继承树：** 抽象基类。后续的 TitleScene、MenuScene、GameplayScene、ResultScene、SettingsScene 均继承自它。

**方法说明：**

| 方法 | 作用 |
|------|------|
| onEnter() | 场景被激活时调用（加载资源、初始化状态），默认空实现 |
| onExit() | 场景被停用时调用（释放资源），默认空实现 |
| handleEvent(event) | 处理键盘/鼠标事件，默认空实现 |
| update(float dt) | **纯虚函数** — 每帧更新逻辑，派生类必须实现 |
| render(sf::RenderTarget&) | **纯虚函数** — 每帧渲染画面，派生类必须实现 |
| requestPush(scene) | 请求压入新场景（委托 SceneManager，延迟执行） |
| requestPop() | 请求弹出当前场景（延迟执行） |
| requestReplace(scene) | 请求替换当前场景（延迟执行） |
| setSceneManager(mgr) | 设置 SceneManager 指针，供派生类发起切换请求 |
| getSceneManager() | 获取 SceneManager 指针 |

**核心成员：**

| 成员 | 类型 | 作用 |
|------|------|------|
| m_sceneManager | SceneManager* | 指向场景管理器的指针，派生类通过它调用 requestPop 等方法 |

**延迟切换机制：**
```
update() 内调用 requestReplace(B) → 写入 PendingChange → 不立即执行
update() 返回后 → SceneManager::applyPendingChanges() → 安全切换
```

### 1.3 SceneManager 类

**文件清单：** src/SceneManager.h · src/SceneManager.cpp

**继承树：** 无继承。独立类。

**方法说明：**

| 方法 | 作用 |
|------|------|
| pushScene(scene) | 将场景压入栈顶 → 调用场景的 onEnter() |
| popScene() | 弹出栈顶场景 → 调用 onExit() → 新栈顶调用 onEnter() |
| replaceScene(scene) | 替换栈顶场景 → 旧场景 onExit() → 新场景 onEnter() |
| handleEvent(event) | 将事件分发给栈顶场景 |
| update(float dt) | 更新栈顶场景 → 帧末执行延迟切换 |
| render(target) | 渲染栈顶场景 |
| isEmpty() | 返回栈是否为空 |

**核心成员：**

| 成员 | 类型 | 作用 |
|------|------|------|
| m_scenes | vector<unique_ptr<IScene>> | 场景栈，栈顶为当前活动场景 |
| m_pending | PendingChange | 缓存一个切换请求，帧末执行 |

**内部结构体 PendingChange：**

| 字段 | 作用 |
|------|------|
| action | 枚举：None / Push / Pop / Replace |
| scene | unique_ptr<IScene>，Push 和 Replace 时需要传递的新场景 |

**第六~七阶段更新：**
- 新增静态成员 `s_transitionAlpha`（float）：跨场景共享的渐黑过渡遮罩透明度。TitleScene→MenuScene 时写入 0→1，MenuScene 和 PackScene 的 update() 中自动衰减回 0，实现统一的淡入淡出效果。
- 新增静态成员 `s_exitRequested`（bool）：MenuScene Exit 按钮设置为 true，Application::run() 检测后关闭窗口。

### 1.4 main.cpp 程序入口

**文件清单：** src/main.cpp

**逻辑流程：**

```
main()
  └─ GetModuleFileName 定位 exe 路径 → chdir 到项目根目录
  └─ Application app("指尖振律", 1280, 720)
  └─ app.getSceneManager().pushScene(TitleScene)
  └─ app.run()
```

**第七阶段更新：** 新增 `#include <windows.h>` + `#include <direct.h>` + `#include <filesystem>`，通过 `GetModuleFileNameA` 自动获取 exe 所在目录并向上回溯至项目根目录 `cpp_game/`，确保双击 EXE 时也能找到 `assets/fonts/` 和谱面/音频文件。

## 第七阶段：判定系统重构 + Bug 修复（2026-07-11）

### 7.1 判定系统重构：像素距离 → 时间判定

**改动文件：** GameplayScene.h · GameplayScene_Update.cpp · GameplayScene_Judgment.cpp

**背景：** 旧判定基于 `|note.y - 550px|` 像素距离。同一时间到达的音符因生成时机不同、下落速度受异象影响，导致判定窗口实际宽度不稳定，采音体验奇怪。

**新判定窗口（时间差）：**

| 时间差 | 判定 | 加分 | Combo |
|--------|------|------|-------|
| < 40ms | Perfect | +100 | +1 |
| < 100ms | Great | +50 | +1 |
| < 200ms | Good | +25 | +1, HP-3 |
| 200~300ms | Miss | +0 | 归零, HP-8 |
| > 300ms | 不响应 | — | — |

**关键改动：**
1. `GameplayScene.h`：像素窗口变量（m_perfectWindow 等）改为时间窗口变量（m_perfectTimeWindow 等）
2. `spawnNotes()`：`nr.y = 100` → `nr.y = m_judgmentLineY - speed × (targetTime - currentTime)`
3. `checkJudgment()`：`|note.y - 550|` → `|musicTime - targetTime|`；空按>300ms 不响应
4. `autoMissCheck()`：`y > 700` → `currentTime > targetTime + 300ms`

**收益：**
- 视觉变速（NoteSpeedChange 异象）不影响判定窗口
- BPM 变化不影响判定（绝对时间）
- 音符始终精准在 targetTime 到达判定线
- 空按不再误判为 Miss

### 7.3 新增谱面：Infinite Strife（Phigros 转换）

**来源：** 桌面 `infinite strife.json`（Phigros RPE 格式，6.2MB）

**转换：** Python 脚本解析 RPE 格式：
- 时间：RPE `[beat, num, den]` = `beat + num/den` 拍 → 秒（÷BPM×60）
- 轨道：X 坐标 `[-525, 525]` 均分 4 段 → 轨道 0-3
- 类型：Tap(type1) + Flick(type4) → tap；Hold(type3) 时长均为 0，丢弃；Drag(type2) 丢弃；Fake 丢弃

**输出：** `InfiniteStrife.json`（1146 tap，2:45，BPM198）
